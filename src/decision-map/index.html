Fast Rule

  1. If the client can change its LLM endpoint, use AI Gateway.
  2. If the user is browsing the Internet, use Secure Web Gateway.
  3. If an agent needs tools through MCP, use MCP Server Portal.
  4. If the data is already inside SaaS, use CASB.
  5. If the app is public-facing, add AI Security for Apps.
  6. If employees need governed agents and app creation, use Cloudflare OS.
  7. If you are building the agent or private path, use Developer Platform and Workers VPC.
Inline controls AI Gateway, SWG, MCP Portal through Gateway, and reverse proxy protections can inspect traffic while it flows.
Out-of-band checks CASB uses provider APIs to find risky SaaS posture and sensitive content after storage.
Owned execution Cloudflare OS fits governed employee work; Workers, Agents SDK, and remote MCP servers fit custom engineering.
Private reachability Workers VPC connects Workers to private APIs and can apply Gateway policies to Worker public egress.

How the pieces fit together

A comprehensive customer architecture usually has several AI paths at once: employees using web AI, coding agents calling LLM APIs, MCP-enabled tools reaching approved servers, employees building governed work in Cloudflare OS, public AI apps behind Cloudflare, and Workers-based agents reaching private networks.
